## Why this order

The design's option 6a removes the Explore view, moves seeds into the
rail and replaces the focus projection with an additive Scope model
(collections stay visible, hops add neighbours, rows filter by
checkbox). That is the answer to D1 and makes D2 moot, so neither is
fixed on the current focus model. B4's labels depend on which toolbar
entries survive, so they are decided inside the design brainstorm. B6
is fixed before hop fetching is built on the same seed pipeline.

## Stage 2: design, layer 1, rail Scope and toolbar reduction

Process: `superpowers:brainstorming`, then spec in
`docs/superpowers/specs/`, plan in `docs/superpowers/plans/`, then
subagent-driven development. Feature branch `graph-scope-rail`.

Scope of the layer: Scope section in `graphKeyRail.ts` (count line,
presets, Seeds rows with hover, remove, Add seed, Collections checkbox
tree with "Not in Zotero"), toolbar reduced to Filter, Similar, Export,
Refresh, search; Explore identity, history arrows, Explore settings,
Add Node and Seeds popover removed; focus projection retired in favour
of the additive model. Resolves D1 and D2. Decides B4's item-menu
labels ("New Graph from N items", "Show in", "Refresh").

Brainstorm must state explicitly which behaviours from
`2026-09-05-explore-toolbar-controls-design.md`,
`2026-09-07-seed-entry-points-design.md` and
`2026-09-07-refresh-preserves-state` (Explore settings persistence,
seed popover, sticky selects) survive, are moved into the rail, or are
deleted, so the spec does not silently drop approved work.

the union of `citedBy` over visible hop k papers through the existing
